# 项目 3：「数学可触摸」反向函数绘图器

> Touchable Math — 把"输入公式→画图"反过来：随手画一条曲线，系统实时告诉你"这是什么函数、为什么"。
> 定位：单人可执行的纯前端教育玩具。本文档为绿地项目实施计划（v0.1）。

---

## 1. 一句话定位与目标用户

**一句话定位**：一个"手绘曲线 → 实时拟合出最简洁解析表达式 → 动画解释为什么"的浏览器端数学物理直觉训练玩具。

**目标用户**（按优先级）：

| 用户群         | 场景                                         | 关键诉求                                       |
| -------------- | -------------------------------------------- | ---------------------------------------------- |
| 高中生（核心） | 学二次函数/三角函数/指数时"背公式但没感觉"   | 画一个抛物线，看到 `y = ½gt²` 跳出来的瞬间惊喜 |
| 大学低年级     | 普物实验课，想快速判断数据是指数衰减还是幂律 | 拟合质量指标 + 残差可视化                      |
| 教师           | 课堂演示"函数族长什么样"                     | 投影友好、零安装、可分享链接                   |

**非目标**：不做通用科学计算工具（不与 Desmos/GeoGebra 正面竞争），不做精确数值拟合软件（不与 Origin/MATLAB 竞争）。差异化全部押在**"反向 + 解释动画"**上。

**成功定义（玩具级 KPI）**：用户首次画线到看到表达式 < 5 秒；单次会话平均画 ≥ 3 条曲线（说明"好玩"）。

## 2. MVP 范围（先支持哪些函数族）

原则：**模板库要小而准，宁可拟合不出也不要拟合出怪东西**。MVP 共 8 个函数族、每族 ≤ 3 个自由参数：

| #   | 函数族        | 形式                             | 教学钩子                  |
| --- | ------------- | -------------------------------- | ------------------------- |
| 1   | 线性          | `y = ax + b`                     | 斜率=变化率               |
| 2   | 二次          | `y = a(x−h)² + k`                | 自由落体 `½gt²`、抛体运动 |
| 3   | 三次（简化）  | `y = ax³ + bx`                   | 拐点直觉                  |
| 4   | 正弦          | `y = A·sin(ωx + φ) + c`          | 单摆、声波、潮汐          |
| 5   | 指数增长/衰减 | `y = A·e^(kx) + c`               | 放射衰变、咖啡冷却、复利  |
| 6   | 幂函数        | `y = a·x^n`（n 取 ±½, ±1, 2, 3） | 开普勒第三定律            |
| 7   | 对数          | `y = a·ln(x) + b`                | 分贝、地震震级            |
| 8   | 双曲/反比例   | `y = a/x + b`                    | 玻意耳定律                |

**MVP 明确不做**：

- 分段函数、隐函数（圆、心形线）、参数曲线 → v2
- 多条曲线叠加比较 → v2
- 自由组合表达式（如 `sin(x)·e^(−x)`）→ v2，仅在模板库加入 1 个"阻尼振荡"特例 `A·e^(−kx)·sin(ωx+φ)`，因为它是物理课明星
- 账号系统、云存储 → 永不做（分享用 URL 编码参数）

**MVP 交互范围**：单画布手绘（鼠标/触屏）、实时显示 Top-3 候选表达式及置信度、点击候选 → 播放解释动画、"物理外衣"开关（把 `y=ax²` 显示成 `h=½gt²` 并标注 g≈9.8）。

## 3. 符号回归技术路线对比

| 路线                                         | 原理                                                                       | 延迟                           | 包体积                                                        | 结果可控性                             | 教学可解释性                     | 实现成本                                       |
| -------------------------------------------- | -------------------------------------------------------------------------- | ------------------------------ | ------------------------------------------------------------- | -------------------------------------- | -------------------------------- | ---------------------------------------------- |
| **A. 模板库拟合（推荐）**                    | 对每个函数族跑非线性最小二乘（Levenberg-Marquardt），用 MDL/AIC 选最简模型 | **< 50ms**（8 族 × 并行）      | ~0（手写或 ml-levenberg-marquardt，几十 KB）                  | **完全可控**，输出永远在白名单内       | **最强**：每个模板可预制专属动画 | 低（2 周内可跑通）                             |
| B. 遗传编程（自写 GP / gplearn 思路移植 JS） | 表达式树随机演化 + 适应度选择                                              | 秒级，难保 200ms               | 小                                                            | 差：常产出 `sin(sin(x+x))·0.97` 类怪物 | 弱：怪表达式无法配动画           | 高（简化、保护除法、bloat 控制全是坑）         |
| C. PySR / Julia 编译 WASM                    | 工业级符号回归引擎                                                         | 冷启动数秒，单次拟合数百 ms~秒 | **数十 MB**（Julia runtime WASM 化不成熟，2026 年仍属实验性） | 中（可设算子白名单）                   | 中                               | 极高，单人不现实                               |
| D. LLM API（发点集让模型猜公式）             | prompt 工程                                                                | 1–5s，网络依赖                 | 0                                                             | 不稳定、幻觉                           | 看似强实则不可靠                 | 低，但**违背纯前端/隐私/离线原则**，且按次计费 |

**推荐：A 为主干，B 作 v2 彩蛋。**

理由：

1. **教育产品的核心不是"能拟合任何函数"，而是"拟合结果一定是课本上认识的函数"**。模板库恰好把搜索空间限制在教学大纲内——这在通用符号回归里是缺陷，在本产品里是特性。
2. 只有结果可枚举（8 族），才能为每个结果**预制高质量解释动画**（第 5 节）。GP/PySR 的开放式输出无法预制动画，只能生成泛泛的解释。
3. 8 个模板各跑一次 LM 拟合，总计算量 < 10⁵ 次浮点函数求值，主线程都够，放 Web Worker 更是绰绰有余，200ms 预算轻松达成。
4. 模型选择用 **MDL 风格评分：`score = n·ln(RSS/n) + λ·complexity`**，complexity = 参数个数 + 函数族先验复杂度（线性 < 二次 < 正弦）。平局时永远选更简单的——这本身就是一个可以讲给学生的"奥卡姆剃刀"教学点。
5. v2 彩蛋：当 8 族最佳拟合 R² 均 < 0.85 时，提示"这条曲线超出了我的课本，要不要看遗传算法现场进化一个？"——把 GP 的慢和怪反过来做成**演化过程可视化**的教学内容，扬长避短。

## 4. 实时性设计（手绘输入 → 200ms 内反馈）

### 4.1 输入管线（边画边处理，pointermove 驱动）

```
原始 pointer 点流（不均匀、抖动、可能回笔）
  → ① 单调化：按 x 排序去重；检测回笔（x 倒退段）→ 取 y 均值合并（默认只支持函数图像，y 单值）
  → ② 降噪：5 点移动平均 或 一维高斯核（σ≈2px）；笔速快的段加大窗口
  → ③ 重采样：沿 x 等距重采样到固定 N=64 点（线性插值）——拟合输入维度恒定，延迟可预测
  → ④ 归一化：x,y 映射到 [0,1]，拟合后再反变换参数（避免数值病态，LM 收敛快 5–10 倍）
```

可选增强（不进 MVP）：Ramer–Douglas–Peucker 简化 + Catmull-Rom 平滑，用于"笔迹美化回显"。

### 4.2 拟合调度（Web Worker + 防抖 + 渐进反馈）

- **架构**：主线程只负责画布渲染；拟合全部在 1 个 Web Worker 内（Comlink 或裸 postMessage）。
- **触发**：
  - 画线过程中：每 120ms 节流触发一次"快速拟合"（仅线性/二次/正弦 3 个便宜模板，N=32 点），结果以半透明虚线实时叠加——制造"它在猜我"的体验。
  - `pointerup` 后：跑全部 8 族完整拟合（N=64），目标 ≤ 150ms。
- **预算分解**（pointerup 后）：降噪重采样 ~2ms；8 族 LM 拟合（每族多起点 3 组初值防局部最优）~8×3×3ms ≈ 70ms；MDL 排序 ~1ms；postMessage 序列化 ~2ms；渲染 ~16ms（一帧）。**总计 ≈ 90ms，预算余量 >2 倍**。
- **初值策略（LM 成败关键）**：正弦用 FFT 主频估 ω；指数用 `ln|y−c|` 线性化估 k；二次用三点法。坏初值是 GP 不需要、模板法必须解决的核心工程点，第一周就要做。
- **抢占**：新一轮触发时向 Worker 发 `generation` 序号，旧任务结果带旧序号直接丢弃（LM 单次 <10ms，无需真中断）。
- **兜底**：若设备慢导致 >200ms（用 `performance.now()` 实测），自动降级 N=32 + 砍掉双起点，并埋点记录。

### 4.3 反馈呈现

- 拟合曲线以**动画描线**（300ms ease-out）叠加在手绘原线上，残差 > 阈值的区段用浅红色带标出。
- 表达式用 KaTeX 渲染，参数数字**就近取整为"教学友好值"**（9.81→"≈ ½·9.8·t²"，0.499→½，3.13→π），原始值悬停可见。这是"教育玩具"和"拟合软件"的关键分水岭。

## 5. "为什么是这个式子"的教学动画设计

总原则：动画回答的不是"参数怎么算出来的"（最小二乘对中学生是黑盒），而是**"这个函数族有什么独一无二的指纹，你的曲线恰好有这个指纹"**。每族一条"指纹"，预制成 3–5 步、每步 2–4 秒、可暂停回放的分镜。

### 例 1：二次函数（用户画了条下落抛物线 → `y = ½g t²`）

> 指纹：**等时间隔，落距按 1 : 3 : 5 : 7 奇数列增长**（伽利略奇数定律）。

分镜（总长 ~12s）：

1. 用户手绘曲线淡化为灰色底图，沿曲线放一个小球，从顶点开始下落，**沿用户自己画的轨迹**运动。
2. 时间轴打出等间隔节拍（嘀、嘀、嘀），每拍在曲线上落一个标记点。
3. 相邻标记点之间的竖直落距被拉出来排成柱状：高度比清晰地呈 **1 : 3 : 5 : 7**，数字逐个弹出。
4. 旁白字幕：「等时间内落距按奇数增长——这是平方关系独有的指纹。累加 1+3+5+7 = 16 = 4²，所以总落距 ∝ t²。」
5. 表达式逐项点亮：`y = ½ · g · t²`，点 `g` → 柱状图整体缩放演示"g 变大曲线变陡"；点 `½` → 展示 v-t 三角形面积的一半（速度从 0 匀加，平均速度是末速一半）。
6. 收尾：用户的灰色手绘线与橙色拟合线重叠对比，残差带闪一下：「你画的线，95% 贴合自由落体。」

### 例 2：指数衰减（用户画了条咖啡冷却曲线 → `y = A·e^(−kt) + c`）

> 指纹：**半衰期恒定——无论从哪里开始，掉到剩一半所用时间都一样**。

分镜（总长 ~12s）：

1. 在用户曲线上任取一点，画水平虚线到"当前高度的一半"，量出所需横向距离，标注 `t½`。
2. 换一个起点重复，再换一个：三段 `t½` 线段飞到屏幕下方排队，**长度完全相等**。字幕：「每过同样的时间就剩一半——只有指数函数做得到。」
3. 反例对比 0.5 倍速闪过：在一条二次曲线上做同样测量，三段长度明显不等 →「所以你画的不是抛物线」。这一步是**模型选择的可视化**，直接回答"为什么不是别的式子"。
4. 表达式点亮：`y = A·e^(−kt) + c`。拖动 `k` 滑块 → 曲线变陡、`t½` 标尺变短，实时联动；`c` 高亮为水平渐近线（"咖啡最终凉到室温，不是 0 度"）。
5. 物理外衣：一杯咖啡的温度计动画沿曲线下降，`c` 标注为「室温」。

**工程化**：动画 = 时间轴驱动的 Canvas 绘制指令序列（自写 ~200 行 timeline 即可，不引大型动画库）；每族一个动画脚本模块，输入为拟合参数，分镜内所有几何量据实计算（小球真的沿用户的曲线走，而非播放预渲染视频）——"动画用的是你画的线"是体验的灵魂。

## 6. 技术栈（纯前端）

| 层                              | 选型                                                                            | 理由                                                           |
| ------------------------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 框架                            | **Vite + React 19 + TypeScript strict**                                         | 单人熟悉度优先；无 SSR 需求，不用 Next.js                      |
| **绘图：Canvas 为主，SVG 为辅** | 手绘层、拟合曲线层、动画层 = 3 个叠放 `<canvas>`；坐标轴/标签/UI 控件 = SVG/DOM | 见下方取舍分析                                                 |
| 数学                            | 自写 LM 拟合（~300 行）或 `ml-levenberg-marquardt`；FFT 自写 radix-2（~80 行）  | 避免引入 math.js 全家桶（500KB+），表达式求值手写 8 个函数即可 |
| 公式渲染                        | KaTeX                                                                           | 比 MathJax 快一个量级，体积可裁剪                              |
| 计算隔离                        | Web Worker（裸 postMessage）                                                    | 拟合不阻塞绘制                                                 |
| 动画                            | 自写 rAF timeline（无 GSAP）                                                    | 需求是确定性分镜，不需要通用动画库                             |
| 状态                            | React state + URL 参数（分享：函数族 id + 参数 base64 进 query）                | 零后端                                                         |
| 测试                            | Vitest：拟合精度（合成数据加噪声 → 参数误差 <5%）、模型选择正确率、重采样幂等性 | 核心算法必须有测试                                             |
| 部署                            | Vercel / GitHub Pages 静态托管                                                  | 纯静态，零运维                                                 |

**Canvas vs SVG 取舍**：

- 手绘输入每秒产生 60–120 个点，SVG 增量改 path 的 d 属性会触发布局/样式重算，移动端掉帧风险高；Canvas 增量画线段为 O(1)。**手绘与动画层必须 Canvas**。
- 坐标轴、刻度、拖动手柄、残差提示等"少量、需命中检测、需 CSS 过渡"的元素用 SVG/DOM，省去手写 hit-test。
- 高分屏统一 `devicePixelRatio` 缩放封装一次。
- 不用 WebGL：点数 ≤ 几千，2D context 足够，留住实现简单性。

**移动端要点**：`touch-action: none` 防滚动劫持；`pointerEvents` 统一鼠标/触摸/笔；画布最小高度 60vh，控件下置拇指可达。

## 7. 里程碑（4 阶段）

| 阶段            | 周期      | 内容                                                                                               | **可验证交付物（验收标准）**                                                                                                                                                      |
| --------------- | --------- | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **M1 引擎可信** | 第 1–2 周 | 输入管线 + LM 拟合 + 模型选择，无 UI 美化                                                          | 测试页：鼠标画线 → 控制台/简单文本输出 Top-3 表达式。**验收：30 条合成噪声曲线（每族 3–4 条，噪声 σ=3px）模型选择正确率 ≥ 90%，pointerup 到结果 ≤ 200ms（中端手机 Chrome 实测）** |
| **M2 体验闭环** | 第 3–4 周 | 三层 Canvas、实时虚线预测、KaTeX 表达式卡片、教学友好取整、参数滑块联动                            | 可分享的部署 URL。**验收：5 名非开发者用户无指导完成"画→看式子→拖参数"，每人 ≥ 3 条曲线无致命困惑；移动端 Safari/Chrome 实测通过**                                                |
| **M3 会讲课**   | 第 5–7 周 | timeline 动画引擎 + 4 族动画（二次/正弦/指数/线性）+ 物理外衣开关                                  | **验收：二次与指数两条标杆动画完整可播放/暂停/回放，动画几何量来自用户实际曲线（换一条线动画跟着变）；2 名中学生看完能用自己的话复述"奇数定律"或"半衰期恒定"**                    |
| **M4 打磨发布** | 第 8–9 周 | 余下 4 族动画（可降级为静态图解）、URL 分享、低 R² 友好兜底文案、onboarding 引导、埋点（本地优先） | **验收：Lighthouse 性能 ≥ 90；首包 gzip ≤ 300KB（KaTeX 字体除外）；发布到 Show HN / 即刻 / 教师社群各 1 帖，收集 ≥ 20 条真实反馈形成 v2 清单**                                    |

砍单原则：进度落后时，M3 先保 2 个标杆动画，M4 的 4 个动画降级为带高亮标注的静态图解——**引擎准确性和两个杀手级动画不可砍**。

## 8. 主要风险与对策

| #   | 风险                                                                                                                | 概率/影响                     | 对策                                                                                                                                                                                                |
| --- | ------------------------------------------------------------------------------------------------------------------- | ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **过拟合出怪异表达式**：噪声手绘被高自由度模板（三次、阻尼振荡）抢走，输出 `y=0.0013x³+2.97x−0.04` 这类反教学的式子 | 高 / 高（直接摧毁产品信任）   | ① MDL 复杂度罚项 λ 用 30 条标注曲线做网格搜索校准；② **简单优先平局规则**：复杂模型 R² 增益 < 0.03 时强制选简单模型；③ 参数显著性剪枝：`                                                            | a   | <` 阈值的高次项系数直接置零降级函数族；④ 教学取整层把 0.0013 这类残渣吸掉；⑤ 全族 R² < 0.85 时坦诚说"我不确定，再画顺一点试试？"而不是硬给答案 |
| 2   | 手绘质量太差（抖、断笔、回笔、画太短），拟合无从谈起                                                                | 高 / 中                       | ① 回笔合并 + 断笔 600ms 内自动续线；② 点数 < 15 或 x 跨度 < 画布 20% 时提示"再画长一点"；③ onboarding 用幽灵笔迹示范一条抛物线引导首次成功                                                          |
| 4   | 正弦/指数 LM 陷入局部最优（ω、k 初值敏感），同一条线每次结果不同，用户觉得"它在瞎猜"                                | 中 / 高                       | ① FFT 估 ω、对数线性化估 k 的确定性初值（第一周完成）；② 每族 3 组初值取最优；③ 重采样与初值全流程确定性，**同一输入永远同一输出**，写进测试                                                        |
