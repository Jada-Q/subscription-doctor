# 项目 7：「失败博物馆」工程事故交互式复盘

> 把著名工程事故做成浏览器内可交互的仿真展品，让用户"亲手把它弄坏一次"，从而真正理解事故背后的工程与伦理教训。纯前端静态站，单人可执行。

---

## 1. 一句话定位与目标用户

**一句话定位**：一座开在浏览器里的工程事故博物馆——你不是读事故报告，而是亲手转动旋钮、敲下按键，复现塔科马大桥的颤振、Therac-25 的竞态、切尔诺贝利的正反馈，在"亲手弄坏它"的瞬间理解为什么会有人死去，以及哪些工程纪律本可以阻止这一切。

**目标用户**（按优先级）：

| 用户群                            | 动机                             | 设计含义                                         |
| --------------------------------- | -------------------------------- | ------------------------------------------------ |
| 工科/CS 学生与年轻工程师          | 工程伦理课、软件安全课的鲜活教材 | 每个展品末尾给出可引用的"教训"小结与原始报告链接 |
| 科普爱好者（HN / 知乎 / B站受众） | 对"著名灾难背后的机制"好奇       | 交互门槛低：30 秒内能玩出第一个"坏掉"的瞬间      |
| 教师/培训者                       | 课堂演示素材                     | 每个仿真支持 URL 参数预设状态，可直接投屏演示    |

**非目标**：不是精确工程仿真工具（不可用于真实设计验证），不是事故猎奇合集，不做用户系统/评论区（纯静态站）。

---

## 2. MVP 范围

**结论：MVP 先做 Therac-25，塔科马紧随其后作为第二展品。**

### 权衡分析

| 维度                     | Therac-25（竞态条件）                                                                                                                                                | 塔科马海峡大桥（气动弹性颤振）                                                                                                    |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 仿真实现难度             | **低**：本质是一个有限状态机 + 共享变量 + 时序窗口，纯逻辑仿真，无数值稳定性问题，TypeScript 一周内可写出可信的简化模型                                              | **中高**：需要二自由度（竖向+扭转）气弹耦合 ODE，负阻尼颤振的数值积分要调参才能既稳定又"看起来对"；可视化（桥面扭转动画）工作量大 |
| 教学冲击力               | **高且独特**：用户亲手快速敲入"X→上移→E→回车"的 8 秒内序列，屏幕显示 MALFUNCTION 54，然后告诉他剂量超了 100 倍——这种"我刚才那几下键盘杀了人"的体感是文字永远给不了的 | 高但**已被消费**：塔科马的视频人人看过，"看桥扭"的新鲜感低；新增价值在于"亲手调阻尼让它稳定下来"的反向操作                        |
| 可验证性（避免以讹传讹） | Leveson & Turner 1993 论文给出了竞态机制的权威描述，状态机可以直接对照论文建模                                                                                       | 颤振机制有教科书级共识（Billah & Scanlan 1991 澄清了"共振"的讹传），参数可查                                                      |
| 对"软件人"受众的命中率   | 直接命中（软件并发 bug 致死的开山案例）                                                                                                                              | 间接                                                                                                                              |
| MVP 风险                 | UI 还原 VT100 终端 + 时序判定，风险集中在"教学引导"而非技术                                                                                                          | 风险集中在物理模型调参，可能吃掉数周                                                                                              |

**理由总结**：Therac-25 的仿真难度最低（状态机，无物理数值问题）、教学冲击力对核心受众（软件工程师/学生）最高、史料最权威可考。它能让 MVP 在 2-3 周内上线并验证"亲手弄坏"这一核心体验是否成立；塔科马的物理仿真则在框架验证后做，避免一开始就陷入调参泥潭。

### MVP 包含

- 站点骨架：首页（博物馆大厅，展品卡片列表，未完成展品标"筹备中"）+ 展品页模板（见第 3 节）
- 展品一：Therac-25 完整展品（状态机仿真 + 终端 UI + 五段式内容）
- 严肃性声明页（见第 6 节）
- 静态部署（Vercel/GitHub Pages）

### MVP 不包含

- 塔科马/切尔诺贝利/福岛（占位卡片）
- 多语言（先中文，文案结构上为 i18n 留键值分离）
- 成绩/分享卡片、音效

## 3. 单个展品的内容结构模板

每个展品是一个五幕式的纵向滚动页面，**交互仿真放在第二幕**——先给最少的必要背景，尽快让用户上手，玩完再回头深挖。

```
exhibit/
├── 第一幕：历史背景（2-3 分钟阅读量）
│   ├── 时间、地点、涉事系统是干什么的（一句话能懂）
│   ├── "事故前夜"：当时的人为什么觉得它是安全的
│   └── 关键人物/机构（克制，不做人物猎奇）
├── 第二幕：交互仿真（核心，停留 5-15 分钟）
│   ├── 引导任务 1：先让系统正常工作一次（建立"它本来是好的"的体感）
│   ├── 引导任务 2：按提示复现事故条件，亲手弄坏它
│   ├── 自由探索：开放参数，附"你能找到第二种弄坏它的方法吗"
│   └── 安全阀提示：仿真为简化模型，与真实系统的差异清单（折叠面板）
├── 第三幕：事故时间线（垂直时间轴组件）
│   ├── 逐条事件：日期 + 发生了什么 + [来源编号]
│   ├── 标红"本可以拦住它的时刻"（每条事故 2-4 个决策点）
│   └── 死难者与伤者：克制陈述事实数字，不配煽情图
├── 第四幕：教训（工程伦理落点）
│   ├── 直接技术教训（如：不要复用安全攸关的硬件互锁逻辑到软件）
│   ├── 系统性/组织教训（如：异常报告被当作噪音忽略）
│   ├── "今天它换了个名字还在发生"：1-2 个现代对应案例
│   └── 可引用小结（一段话，方便教师引用）
├── 第五幕：延伸阅读
│   ├── 一手来源（事故调查报告、原始论文，标注获取方式）
│   ├── 优质二手解读（书/纪录片/讲座）
│   └── 本展品仿真模型的简化说明与源码链接
```

工程上对应一个 `ExhibitLayout` 组件 + 每展品一个内容数据文件（MDX 或结构化 JSON）+ 一个仿真组件，五幕结构由模板强制保证一致性。

## 4. 仿真技术方案

### 总原则：教学保真度 > 物理保真度

每个模型只需满足两条：(a) **定性行为正确**——该发散的发散、该锁死的锁死、参数影响方向正确；(b) **机制可信**——模型里的因果链与真实事故的因果链同构。明确放弃定量精度，并在页面内公开简化假设（第 3 节"安全阀提示"）。

### 渲染选型：Canvas 2D 为主，不上 WebGL

- 四个展品的可视化都是 2D 示意（桥梁侧视/截面扭转、终端屏幕、反应堆芯格点热力图、电源拓扑图），Canvas 2D + `requestAnimationFrame` 足够，60fps 无压力。
- WebGL/Three.js 带来的 3D 收益（塔科马 3D 桥面）属于锦上添花，成本（学习+资产制作）不匹配单人项目，**明确排除出前四个展品**。
- 架构：`仿真核心（纯 TS，零 DOM 依赖，可单测）` ↔ `固定步长循环（accumulator 模式，dt=1/120s，渲染插值）` ↔ `Canvas 渲染层`。仿真核心可单测是底线，因为它就是展品的"史实正确性"所在。
- 框架：Vite + React（或 Preact）做 UI 壳与内容排版，仿真画布内部不走 React 状态，避免每帧 re-render。

### 各展品模型保真度取舍

**Therac-25 —— 离散事件状态机（无物理）**

- 建模为：`治疗模式状态机（X光/电子）` + `磁偏转台位置（需 ~8 秒移动）` + `数据输入子程序（Datent）与键盘处理的共享标志位`，按 Leveson & Turner (1993) 论文中的竞态描述实现。
- 关键简化：不模拟 PDP-11 真实指令时序，用"逻辑时序窗口"（操作员在 Magnet 子程序完成前修改了模式参数 → 标志位检查被绕过）复现同一因果结构。
- UI：复刻 VT100 风格终端（等宽字体 + 磷光绿），用户真的用键盘输入 `X`、`↑`、`E`、`Enter`；触发后显示真实的 `MALFUNCTION 54` 报错——和当年操作员看到的一样语焉不详，这本身就是教学点（错误信息设计也是安全的一部分）。
- 附带可视化：旁边并排一个"上帝视角"面板，实时显示状态机内部变量与束流/偏转台真实状态，让用户看见"屏幕说的"与"机器做的"之间的裂缝。

**塔科马 —— 2-DOF 气弹耦合 ODE**

- 模型：桥面截面二自由度（竖向位移 h、扭转角 α），气动自激力用 Scanlan 颤振导数的简化线性形式（系数取教科书量级即可），RK4 固定步长积分。
- 用户可调：风速 U、结构阻尼比 ζ、（进阶）截面形式（H 形开口截面 vs 封闭箱梁，体现现代桥梁为何不再塌）。
- 关键取舍：不做 CFD、不做涡脱落细节；颤振临界风速随阻尼/截面变化的**趋势**正确即可。数值上需加振幅软限幅（大振幅时非线性饱和），否则发散到 NaN——限幅前的增长段才是教学内容。
- 教学反转点：用户先弄塌它，然后任务变成"给你 3 个改造选项（加阻尼/换截面/限速），把它救回来"。

**切尔诺贝利 —— 点堆动力学 + 少量空间离散**

- 模型：点堆中子动力学（6 组缓发中子 + 反应性方程）+ 空泡系数为正的反馈项 + 氙-135 中毒方程 + 控制棒插入曲线（前 ~1 秒因石墨尖端排水注入**正**反应性）。
- 空间维度：轴向切 10-20 个节点足以展示"棒尖效应从堆底开始"，不做全 3D 堆芯。
- 用户复现 1986-04-26 凌晨的操作序列：降功率→氙坑→拔棒维持功率→低功率试验→按下 AZ-5 → 功率指数飙升。每一步 UI 给出当年操作规程的"红线提示"，用户必须主动越线——体验"违规是一连串看似合理的小决定"。

**福岛 —— 图论 + 简单事件序列（最容易）**

- 模型：电源/冷却系统拓扑图（外部电网、应急柴油机、直流电池、海水泵、RCIC/IC 冷却系统为节点），地震/海啸作为事件依次摧毁节点，剩余衰变热按指数衰减曲线积分升温。
- 交互：用户重新设计拓扑（柴油机放高处？增加移动电源接口？电池容量翻倍？）然后重放同一场海啸，看堆芯温度曲线是否越过损毁线。本质是一个"防御纵深"的可玩沙盘，无连续物理仿真难点。

## 5. 历史考据流程

事故复盘最大的声誉风险是以讹传讹（例：塔科马"共振说"流传了几十年，Billah & Scanlan 1991 专文澄清其为气动弹性颤振；切尔诺贝利的流行叙事大量来自剧集而非 INSAG 报告）。流程如下：

1. **来源分级制**，每个展品建 `sources.md`：
   - **A 级（可作为事实陈述依据）**：官方事故调查报告（INSAG-7、日本国会事故调查委员会报告、FDA/AECL 文档）、同行评审论文（Leveson & Turner 1993；Billah & Scanlan 1991）、法庭/听证记录。
   - **B 级（可参考，需 A 级佐证）**：权威书籍（如 Leveson《Safeware》、Higginbotham《Midnight in Chernobyl》）、工程学会出版物。
   - **C 级（仅用于叙事灵感，禁止作为事实来源）**：维基百科、影视剧、科普视频。维基百科只用其参考文献列表当索引。
2. **逐句溯源**：第三幕时间线与第四幕教训中的每一条事实性陈述必须带 `[n]` 角标指向 A/B 级来源；写不出角标的句子删掉或改写为明确标注的"推测/争议"。
3. **流行讹传清单**：每个展品维护一节"常见误解"（如"塔科马是共振"、"切尔诺贝利操作员都是莽夫"），主动辟谣——这反而是站点的差异化内容。
4. **仿真模型对照表**：仿真中每个机制（如棒尖正反应性）写一行"模型行为 ↔ 报告原文出处"，放在第五幕的简化说明里。
5. **死难者信息红线**：人数、姓名只采用官方确认口径；有争议的（切尔诺贝利长期死亡人数）并列给出不同机构估计区间及出处，不自行选边。
6. **勘误通道**：页脚放 GitHub Issues 链接，承诺事实性错误 72 小时内修正并在页面留勘误记录。

## 6. 叙事与情感设计

核心矛盾：交互的"游戏感"与死难者的真实性。原则：**严肃来自克制与具体，猎奇来自渲染与抽象。**

1. **入馆声明**：首页与每个展品页头部有一段固定的、不可跳过滚动区的声明："本馆展示的事故均造成真实的死亡与伤害。我们让你亲手复现它们，不是为了娱乐，而是因为我们相信：理解失败的机制，是对死难者最有分量的纪念。"
2. **不游戏化死亡**：没有分数、没有"成就解锁：堆芯熔毁！"、没有爆炸音效与粒子特效。弄坏系统的瞬间，画面处理是**安静的**——例如 Therac-25 触发过量照射时，终端只显示那行真实的 `MALFUNCTION 54`，停顿两秒，然后浮现一行小字："1986 年 3 月 21 日，泰勒诊所。Ray Cox 收到了约 100 倍处方剂量。他于四个月后去世。"——具体的人、具体的日期，比任何特效都重。
3. **"弄坏"之后必有"在场的人"**：每次用户成功复现事故，仿真区下方展开一段当事人视角的简短史实（操作员当时看到了什么、说了什么，全部出自 A/B 级来源），把抽象的失败重新锚定到人。
4. **语言纪律**：文案禁用感叹号堆砌、禁用"震惊/恐怖/作死"类词汇；对操作员和工程师默认采用系统视角（"系统让这个错误变得容易犯"）而非道德审判——这本身就是 Leveson 学派事故分析的核心立场，也是本站要传递的伦理观。
5. **视觉基调**：博物馆隐喻——深色背景、衬线标题、展签式排版、大量留白；仿真界面拟真（终端、控制台仪表）而非卡通。
6. **尊重的边界测试**：上线前用一个检查清单自审每个展品："如果死难者家属看到这一页，哪一处会让他们觉得被消费了？"有疑问的元素一律删。

| #   | 风险                                                                                   | 影响                         | 对策                                                                                                                                                                |
