# 项目 9：「一平米气象站」超本地微气候网络

> ESP32 + 温湿度/气压传感器（单节点 ≈ 30 元），部署在阳台、屋顶、巷口，众包采集街道级微气候数据。通过数据同化（卡尔曼滤波）与空间插值（克里金/IDW）融合节点观测，生成街道级气候地图，服务城市热岛研究、绿化决策与老人高温预警。

---

## 1. 一句话定位与目标用户

**一句话定位**：用 30 元一个的众包传感器节点，把气象数据的空间分辨率从「每个城市 1-2 个国家站」提升到「每条街道一张图」。

官方气象站间距通常 10-30 km，而城市热岛效应在 100 m 尺度上就能产生 3-8 °C 的温差（柏油马路 vs 林荫巷口）。本项目填补的正是这个「最后一公里」的观测空白。

**目标用户**（按优先级）：

| 用户群                    | 需求                                                    | 付费/参与意愿                |
| ------------------------- | ------------------------------------------------------- | ---------------------------- |
| 城市规划/园林部门、研究者 | 热岛分布图、绿化降温效果评估的实测数据                  | 数据报告付费潜力，中期目标   |
| 社区/街道办、养老服务机构 | 高温日老人活动区域的精细预警（哪条巷子下午 3 点最危险） | 公益合作切入点               |
| 气象/硬件爱好者（节点主） | 「我家阳台的数据上了地图」的参与感 + 自家微气候数据     | 自费购硬件，是网络扩张的引擎 |
| 普通市民                  | 「现在去哪个公园乘凉最划算」的生活决策                  | 流量与传播来源               |

**冷启动判断**：先服务好「节点主」（爱好者），他们既是数据生产者也是第一批用户。研究者和政府是数据消费方，等网络密度起来后再谈。

## 2. MVP 范围

### 阶段策略：先自营验证，再开放众包

**为什么不直接开放众包**：众包数据质量问题（第 5 章）在网络规模小时无法用统计方法兜底；且硬件方案没固化前，让别人花钱组装会烧掉早期口碑。

### MVP-0：自营验证网（第 1-6 周）

- **自己部署 5-10 个节点**，集中在 1-2 平方公里范围内（一个街区/校园/园区），保证插值有意义的空间密度。
- 选址刻意覆盖微气候差异：朝南阳台、朝北阳台、屋顶、巷口树荫、临街马路边——这样第一张地图就能讲出「同一街区温差 4 °C」的故事。
- 至少 1 个节点与附近官方气象站（或一台校准过的参考温度计）做并行对比，量化系统误差。

**MVP-0 做什么**：

- 固化硬件 BOM + 防辐射罩 DIY 方案（第 3 章）
- 节点固件：采样 → WiFi → MQTT 上报，断网本地缓存补传
- 数据管道：MQTT → 时序库 → 基础质控 → IDW 插值 → 静态网页地图（第 4 章）
- 一张可分享的「街区温度地图」截图（传播素材）

**MVP-0 明确不做**：

- App / 用户注册系统
- 太阳能供电（先全部 USB）
- 克里金/卡尔曼（先 IDW，第 6 章）
- LoRa/NB-IoT（先全 WiFi）

### MVP-1：开放众包（第 7-12 周）

- 开放「自组装套件」：BOM 清单 + 烧录好的固件 + 图文组装教程，目标 20-30 个外部节点
- 节点注册流程：网页填写大致位置（隐私处理见第 8 章）→ 生成节点 Token → 固件配网
- 上线节点信誉机制 v1（第 5 章）
- 地图升级为交互式（Leaflet），叠加节点实时值 + 插值热力层

**验证指标（决定继续/转向）**：

- MVP-0：10 节点连续运行 14 天，数据可用率 ≥ 90%，与参考站偏差（加防辐射罩后）≤ 1 °C
- MVP-1：≥ 15 个外部节点主完成部署且 30 天留存 ≥ 60%；至少 1 个机构（社区/研究组）主动询问数据

### 3.2 防辐射罩 DIY 方案（关键质量件）

**为什么必须做**：温度计被太阳直晒，读数可虚高 5-15 °C，数据直接作废。专业 Stevenson 屏百元起，必须 DIY。

**基准方案：花盆托盘叠层式百叶罩**（仿 Davis 辐射罩结构）

```
        ☀
   ┌─────────┐   ← 顶层托盘倒扣（遮阳挡雨）
   ╱─────────╲
  │  ──────── │   ← 3-5 层白色塑料花盆托盘，层间用 M6 长螺杆 +
  │  ──────── │     螺母撑开 2-3 cm 缝隙，空气横向流通
  │  [传感器] │   ← BME280 悬挂在中间层中心，不接触任何塑料面
   ╲─────────╱
   ┌────┴────┐   ← 底层开大孔，热空气不积聚
        │
      扎带固定到栏杆/支架
```

材料：白色塑料花盆托盘 ×5（¥1-1.5/个）、M6×150 mm 螺杆 ×3 + 螺母若干（¥3），共约 ¥7。

**制作要点**：

1. **必须纯白色**托盘（反射率高），脏了要求节点主擦洗——这点写进组装教程的显眼位置
2. 每层托盘中心开孔穿螺杆，传感器吊在第 2-3 层之间的空腔中心
3. ESP32 主控放在罩外的小防水盒里（主控自发热 ≈ 0.3-0.5 °C，绝不能和传感器同罩），传感器用 4 芯线引出 30 cm 以上
4. 安装朝向：北向或常年阴影处优先；距墙面 ≥ 30 cm（墙体蓄热辐射）；离地/离阳台地面 ≥ 1.2 m

**验收方法**：与罩内放置的参考温度计在正午直晒时段对比，DIY 罩 vs 裸晒差值应 ≥ 3 °C，DIY 罩 vs 阴影参考值差 ≤ 1 °C。MVP-0 期间做一次 A/B 实拍记录，既是质检也是传播内容。

### 3.3 供电方案对比

| 方案                       | 成本                                 | 优点                                         | 缺点                                                                        | 结论                                               |
| -------------------------- | ------------------------------------ | -------------------------------------------- | --------------------------------------------------------------------------- | -------------------------------------------------- |
| **USB 5V 常供电**（基准）  | ¥0-8（多数人有闲置充电头）           | 零维护、可常时在线、固件简单（不用深度睡眠） | 需要室外/窗边插座，走线丑                                                   | **MVP 唯一方案**。阳台场景 90% 能解决供电          |

**月成本核算**：VPS ¥24-40 + EMQX ¥0 + 前端托管 ¥0 + 域名摊销 ¥5 ≈ **¥30-45/月**，满足 ≤50 元约束。单台 VPS 是单点，但 MVP 阶段可接受（数据有节点端缓存兜底，宕机不丢历史趋势之外的数据）。

**数据量心算**：100 节点 × 每 5 min 一条 × 288 条/天 ≈ 2.9 万行/天，TimescaleDB 在 2G 内存上毫无压力，留了两个数量级余量。

## 5. 数据质控

众包传感器的现实：假芯片、装在空调外机旁、罩子忘了装、阳台封了玻璃……**必须假设 20-30% 的节点在任意时刻是不可信的**，质控是这个项目的核心技术资产（和硬件一样重要）。

### 5.1 四级异常值剔除流水线

1. **L1 物理范围检查**（节点端+服务端双重）：温度 [-30, 55] °C、湿度 [0, 100] %、气压 [870, 1085] hPa。越界直接丢弃并计入节点错误数。
2. **L2 时间一致性**：单节点温度变化率 > 5 °C / 5 min 视为可疑（传感器抖动或被人为干扰，自然过程极少这么快）；持续 2 小时以上零方差（卡死值）标记为故障。
3. **L3 空间一致性（核心）**：对每个观测，取半径 1.5 km 内邻居节点的同时刻中位数，偏差 > 3 °C 标记可疑、> 6 °C 剔除。用**中位数而非均值**——抗污染。冷启动期（邻居 < 3 个）此层降级为「与最近官方站对比，阈值放宽到 5 °C」。
4. **L4 模式检查**（批处理，每日）：与官方站日变化曲线做相关性分析。一个被太阳直晒的节点，白天系统性偏高、且偏差与太阳高度角相关——这种「日晒指纹」可自动识别并提示节点主「你的防辐射罩可能有问题」。

### 5.2 节点信誉机制

每个节点维护信誉分 R ∈ [0, 100]，初始 50：

- **加分**：连续 24h 无 L1-L3 异常 +1；与邻居中位数偏差长期 < 1 °C 的稳定节点缓慢升至上限
- **减分**：L3 可疑 -2，L3 剔除 -5，L4 检出日晒指纹 -10
- **使用方式**：插值时观测权重乘以 R/100（克里金场景下转化为观测误差方差：R 低 → 方差大）；R < 30 的节点数据不进插值，仅在地图上灰显，并自动给节点主发整改提示（附自查清单：罩子白不白、离墙多远、旁边有没有空调外机）
- **防刷**：信誉只影响数据权重，不兑换任何利益，没有刷分动机；新节点前 7 天为「观察期」，数据进库但不进插值

### 5.3 系统性偏差校准

众包节点常见**恒定偏移**（如某批 BME280 整体偏高 0.4 °C）。对运行 > 30 天的节点，用其与周边高信誉节点的长期中位偏差做一次性 bias 校正（存为节点属性，可随时重算）。这比逐条剔除能挽回大量「精度差但稳定」的节点。

## 6. 空间插值算法

### 三方案对比

|          | IDW（反距离加权）                                  | 克里金（Kriging）                                                                                                  | 卡尔曼数据同化（如 EnKF/OI）                                                                 |
| -------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| 原理     | 加权平均，权重 ∝ 1/d^p                             | 基于半变异函数建模空间相关性的最优线性无偏估计                                                                     | 「背景场（数值预报/前一时刻）+ 观测」按各自误差方差最优融合，带时间维度                      |
| 优点     | 实现半天搞定、零参数调优、对小样本不崩             | 给出**估计不确定度**（地图上能画「这里我们没把握」）、可加协变量（高程/不透水面比例 → 回归克里金，对热岛极有价值） | 理论上限最高：能用 5 个节点 + 气象背景场推出合理全场；时间平滑天然抗噪                       |
| 缺点     | 无方向性、不出不确定度、节点稀疏处出现「牛眼」伪影 | 半变异函数拟合需要 ≥ 30 个左右空间分布良好的点，10 个节点时拟合出的是噪声                                          | 需要背景场数据源（ERA5 再分析延迟 5 天，实时要接数值预报）、实现复杂度高一个数量级、调试黑盒 |
| 计算成本 | 极低                                               | 中（百节点级毫秒-秒级，无压力）                                                                                    | 中高，且工程依赖重                                                                           |

### MVP 推荐：分阶段演进，**MVP-0/1 用 IDW，密度达标后切普通克里金，卡尔曼放 v2**

- **MVP-0（5-10 节点）**：IDW（p=2，搜索半径 2 km）。这个密度下任何高级方法都是在精确地插值噪声，IDW 的简单是优点。地图上节点稀疏区直接做透明度渐隐，诚实展示「这里没数据」。
- **MVP-1 后期（≥ 30 节点且空间分布合理）**：切 **普通克里金（pykrige，球状/指数模型）**，立刻获得不确定度图层——这是对研究者用户的关键卖点，也是和「随便做个热力图」的产品拉开差距的地方。半变异函数每日离线重拟合一次即可，不必每帧拟合。
- **v2（节点 ≥ 100 或拿到实时背景场）**：升级**回归克里金**（协变量：不透水面比例、NDVI、建筑高度，均有免费遥感数据）；同时评估最简版数据同化（Optimal Interpolation：以官方站/预报场为背景场），用历史数据回测真实增益后再决定是否上。卡尔曼不是 MVP 该碰的东西，但架构上把「插值引擎」做成可替换模块，为它留好接口。

**验证方法（所有阶段通用）**：留一交叉验证（LOOCV）——轮流抽掉一个节点，用其余节点插值预测它，统计 RMSE。这是比较 IDW/克里金/参数选择的唯一裁判，每周自动跑一次并记录趋势。

## 7. 里程碑（4 阶段）

### M1：单节点打通（第 1-2 周）

**交付物**：

- 1 个完整节点（含防辐射罩）在自家阳台连续运行 7 天，数据可用率 ≥ 95%
- 数据全链路：MQTT → TimescaleDB → Grafana（临时用）能看到曲线
- 防辐射罩 A/B 实测报告（裸晒 vs 罩内，正午温差照片+数据）
- **验证标准**：罩内读数与阴影处参考温度计偏差 ≤ 1 °C

### M2：自营网络 + 第一张地图（第 3-6 周）

**交付物**：

- 8-10 个节点部署在 1-2 km² 街区，覆盖 ≥ 4 种微环境
- 质控 L1-L3 上线；IDW 插值 + Leaflet 静态地图上线（公网可访问）
- 一篇传播文章：「我们测了 XX 街区，同一时刻温差 X °C」（附地图截图）

## 9. 第一周行动清单（具体到天）

> 前提：本周目标是 M1 的前半程——硬件到手、固件跑通、链路打通。下单要赶在 Day 1，物流是关键路径。

- **Day 1（周一）**：
  - 下单全部硬件 ×3 套（ESP32-C3 ×3、BME280 ×3 ——多买是因为假货率不低、SHT30 ×1 备选、托盘/螺杆/杜邦线）；选有现货次日达的店
  - 注册 EMQX Serverless 免费账号；购买/复用一台轻量 VPS（2C2G）
  - 建 Git 仓库（firmware / pipeline / docs 三目录），写下本计划的 M1 验收标准

- **Day 2（周二）**：
  - VPS 装 Docker，跑起 TimescaleDB + PostGIS + Grafana；建表（`observations` 超表：node_id, ts, t, h, p, qc_flags；`nodes` 表：id, token, lat, lon, lat_fuzzy, lon_fuzzy, reputation）
  - 写桥接 worker 骨架：订阅 EMQX → 校验 → 写库，先用 mosquitto_pub 手发假数据打通全链路
  - 等快递期间用手头任意 ESP32/模拟器先写固件框架

- **Day 3（周三，假设硬件到货）**：
  - 焊接/接线第 1 个节点，I2C 读通 BME280；验真：对照规格书确认有湿度输出（鉴别 BMP280 假货）
  - 固件 v0.1：60 s 采样 → 5 min 聚合 → MQTT 上报（TLS + Token），断网重连逻辑
  - Grafana 看到第一条真实数据曲线 → 截图存档（项目第一个里程碑时刻）
