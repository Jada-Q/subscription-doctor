# 项目 1：家庭电力「心电图」（NILM 电器指纹识别）

## 1. 一句话定位与目标用户

**一句话定位**：一个夹在电表入户线上的「家庭用电听诊器」——不改任何线路、不拆任何电器，从总电流波形中识别出冰箱、空调、热水器等电器的启停事件，进而提供故障预警与独居关怀提醒，所有数据留在家中本地。

**目标用户**（按优先级）：

| 优先级 | 用户画像                                          | 核心诉求                                     |
| ------ | ------------------------------------------------- | -------------------------------------------- |
| P0     | 动手能力强的极客/智能家居爱好者（本人即首位用户） | 看清家里每台电器在干什么、耗多少电           |
| P1     | 关注电费的普通家庭                                | 找出「电老虎」、发现忘关的电器               |
| P2     | 有独居老人的子女家庭                              | 非侵入式（无摄像头）的生活规律监测与异常提醒 |

> 单人项目策略：P0 用户即开发者本人，MVP 阶段不做任何面向 P1/P2 的产品化包装，先把「识别准」这件事做对。

## 2. MVP 范围（明确砍掉什么）

### MVP 做什么（v0.1）

1. **单相单 CT 采样**：一只 CT 夹在入户火线（或某条支路）上，ESP32 以 ≥1 kHz（目标 4 kHz）采样电流波形。
2. **本地事件检测**：检测总功率/电流的阶跃事件（开/关），记录事件时间、ΔI、稳态特征。
3. **3~5 类大功率电器识别**：冰箱（压缩机周期）、电热水壶、电饭煲、空调、电热水器——优先选「指纹明显、功率大」的电器，先用规则/阈值法。
4. **本地 Web 界面**：手机/电脑浏览器访问 ESP32（或局域网内树莓派/旧电脑）查看实时波形、事件流水、识别结果。
5. **数据本地落盘**：事件日志 + 抽样波形片段存 SD 卡或局域网主机，用于后续训练。

### MVP 明确砍掉什么

- ❌ **电压采样与功率因数/谐波相位分析**（MVP 只测电流幅值与波形形状；电压互感/插墙取相位放 v0.2）
- ❌ **三相/多回路支持**（只做单相入户线一路）
- ❌ **神经网络分类器**（MVP 用阈值 + 简单特征匹配，ML 是阶段三的事）
- ❌ **云端任何东西**：无云服务器、无 App、无账号体系、无推送服务（提醒先用局域网内 Bark/ntfy 自托管或干脆不做）
- ❌ **故障预警与独居关怀**（这两个是进阶愿景，依赖识别准确率达标后才有意义，放阶段四且仅做最简版本）
- ❌ **小功率电器识别**（手机充电器、路由器等 <30 W 设备在总线上信噪比太低，不做）
- ❌ **外壳/产品化/给别人装**（面包板 + 3D 打印或塑料盒即可）

### 电气安全注意事项（必须逐条执行）

1. **CT 夹是非侵入的，但入户线区域不是安全区**。夹装 CT 时**先断开总闸**，确认无电后再操作；夹好、扣紧、固定线缆后再合闸。绝不带电在配电箱内布线。
2. **电流输出型 CT 副边绝不可开路**。SCT-013-000 副边开路会感应出危险高压：必须**先接好负载电阻再夹到火线上**；建议在 CT 输出端并联 TVS/稳压管（如双向 5.1 V）做二次保护。若改买内置负载电阻的电压输出型（SCT-013-030 等），此风险消除但量程固定。
3. **只夹单根火线（L）**，火线零线一起夹磁通抵消、读数为零——这是最常见的新手错误。
4. **低压侧与高压侧物理隔离**：CT 信号线与 ESP32 全套电路放在配电箱**外**的绝缘盒中，信号线穿管/固定，避免被箱门夹破皮。
5. **不自制市电电源**：ESP32 用成品 USB 适配器供电，不做任何 220 V 整流降压自制电路。
6. **(v0.2) 电压采样只用 AC-AC 隔离变压器**，绝不用电阻直接分压市电。
7. 配电箱属物业/电工管辖范围的，操作前确认合规；不确定就请持证电工帮忙夹装（约 50–100 元，预算外但值得）。

## 4. 软件架构

数据流：**采样 → 特征提取 → 事件检测 → 分类 → 上报/存储**，前两层在 ESP32 上，后三层 MVP 期放局域网主机（旧电脑/树莓派/常开 NAS），便于快速迭代；最终目标是全部下沉到 ESP32。

```
┌─────────────── ESP32-S3 ───────────────┐      ┌────────── 局域网主机（浏览器/Node）──────────┐
│ [采样层]            [特征层]            │ WS/  │ [事件检测]   [分类层]        [上报层]        │
│ ADS1256 SPI DMA  →  RMS/峰值/谐波/包络  │ MQTT │ 阶跃检测  →  规则引擎/ML  →  本地Web UI      │
│ 4kHz 环形缓冲       每周期(20ms)1帧     │ ───→ │ 事件切片     (后期ONNX/     SQLite落盘       │
│                                        │      │              TFLite)       ntfy本地提醒      │
└────────────────────────────────────────┘      └─────────────────────────────────────────────┘
```

### 各层技术选型

| 层        | 职责                              | 技术选型                                                                                                                                | 理由                                                                                     |
| --------- | --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 采样      | 4 kHz 连续采集电流瞬时值          | ESP32 Arduino/ESP-IDF + ADS1256 SPI（硬件定时器触发 + 双缓冲环形队列）                                                                  | 4 kHz 对 50 Hz 市电每周期 80 点，足够看波形形状；DMA/双缓冲避免丢点                      |
| 特征提取  | 每个市电周期（20 ms）计算一帧特征 | C/C++ 实现：RMS、峰值、峰值因数、过零不对称度；每秒一次 FFT（kissfft/esp-dsp，3/5/7 次谐波幅值）                                        | 把 4 kHz 原始流压缩成 50 帧/秒的特征流，带宽从 ~16 KB/s 降到 <2 KB/s，Wi-Fi 与存储都轻松 |
| 传输      | 特征流 + 按需原始波形片段         | MQTT（mosquitto，自托管）为主；调试期 WebSocket 直连看实时波形                                                                          | MQTT 解耦、断线重连成熟；事件触发时附带前后 2 s 原始波形片段用于训练集积累               |
| 事件检测  | 从特征流中找启停阶跃              | TypeScript（Node 或纯浏览器）：滑动窗均值 + CUSUM/双阈值阶跃检测，去抖（电机启动浪涌单独建模）                                          | 算法简单、迭代频繁，放主机侧改起来快；稳定后移植回 C                                     |
| 分类      | 事件 → 电器标签                   | 阶段一：规则引擎（JSON 规则表：ΔP 区间 + 谐波特征 + 持续时长 + 时段先验）；阶段三：浏览器 ONNX Runtime Web 或 ESP32 TFLite Micro 小模型 | 与算法路线（第 5 节）对应；规则表格式刻意设计成与未来 ML 输出兼容（同一标签集）          |
| 上报/存储 | 可视化、日志、提醒                | 本地 Web UI（Vite + 任意轻框架 + uPlot 画波形）；SQLite 存事件；提醒用自托管 ntfy/Bark 走局域网                                         | 全部本地，零云依赖；uPlot 对高频时序渲染性能好                                           |

> 关键设计决策：**「原始波形不常传、特征常传、事件附波形」**——既保住训练数据，又不被带宽和存储拖死。

## 5. 算法路线（先规则/阈值，后 ML）

### 阶段 A：规则/阈值法（MVP，覆盖 3–5 类大功率电器）

1. **事件检测**：对 1 秒平滑后的电流 RMS 序列做 CUSUM 阶跃检测，ΔI 折算 ΔP（先假定 PF≈1，v0.2 引入电压相位修正）。
2. **特征指纹**（每个事件提取）：
   - 稳态 ΔP 区间（如电热水壶 1800–2200 W 纯阻性、谐波极低）
   - 启动浪涌比（压缩机类启动电流 3–6 倍稳态，持续 <500 ms）
   - 谐波签名（开关电源/变频空调 3 次谐波占比高；纯电阻负载近似正弦）
   - 运行时长与周期性（冰箱压缩机 10–30 min 开、间隔规律；水壶 2–5 min 一次性）
   - 时段先验（电饭煲集中在饭点）
3. **匹配**：JSON 规则表打分匹配，给出标签 + 置信度；冲突时报「未知事件」而不是硬猜。
4. **真值标定**：智能计量插座轮流接在各电器上，其功率日志与总线事件做时间对齐，自动生成带标签训练集——这是 BOM 里第 6 项存在的全部意义。

### 阶段 B：经典 ML（特征向量 → 分类器）

- 特征向量（ΔP、浪涌比、谐波 1–7 次幅值、事件时长、时段）→ 梯度提升树（LightGBM）或 kNN。
- 训练在 PC（Python/scikit-learn），推理导出为纯 if-else / ONNX，在浏览器或 Node 跑。
- 预期收益：把规则法搞不定的「电饭煲 vs 小太阳取暖器」这类同功率段负载区分开。

### 阶段 C：小型神经网络（可选，仅当 B 不够）

- 输入：事件前后 2 s 的电流波形（或其频谱图），1D-CNN，参数量控制在 <100 k。
- 部署：浏览器端 ONNX Runtime Web（与本人技术栈契合），或量化后 TFLite Micro 上 ESP32-S3。
- 参考算法文献：Hart 1992（NILM 开山）、seq2point（Zhang et al. 2018）、NILMTK 工具包。

### 公开数据集（先在数据集上验证算法，再上自家数据）

| 数据集              | 特点                                               | 用途                           |
| ------------------- | -------------------------------------------------- | ------------------------------ |
| **REDD** (MIT)      | 6 户美国家庭，总线高频（15 kHz）+ 分电器低频       | 高频波形特征与事件检测算法验证 |
| **UK-DALE**         | 5 户英国家庭，最长 4 年+，含 16 kHz 高频声学级数据 | 长周期模式（独居关怀场景预研） |
| **REFIT**           | 20 户英国家庭，8 s 粒度                            | 分类器泛化测试                 |

## 6. 隐私设计（数据留在本地）

用电波形能还原一家人的作息（几点起床、是否在家、洗澡时间），敏感度不亚于位置数据。设计原则：

1. **默认离线**：ESP32 与主机只在局域网通信，不出公网；固件中不写任何云端点。路由器侧可对设备 MAC 做断网验证。
2. **数据分级存储**：
   - 原始波形片段：只保留事件前后 2 s，滚动保留 30 天后自动删除；
   - 特征流：保留 90 天；
   - 事件日志（某电器几点开关）：长期保留，但这是最敏感的一层，存储在主机 SQLite，文件级加密（SQLCipher）可选。
3. **提醒不出户**：独居关怀提醒走自托管 ntfy（家人手机连家中 VPN/WireGuard 取通知），而非任何第三方推送；v1 之前干脆只在本地 Web UI 上显示。
4. **关怀场景的知情同意**：被监测的老人必须知情并同意；UI 上明示「监测的是电器使用规律，不是人」；提供一键暂停。
5. **无遥测**：软件不内置任何 analytics/crash 上报；调试日志只写本地。
6. **开源即审计**：固件与主机端代码开源，隐私承诺可被第三方验证。

## 7. 里程碑（4 阶段）

### 阶段一：硬件跑通 + 看见波形（第 1–3 周）

- 交付物：
  1. CT 安全夹装在入户线（或先用插线板支路演练），ESP32 + ADC 以 ≥1 kHz 稳定采样 24 h 无丢帧；
  2. 浏览器实时波形页面：能肉眼看到开水壶时电流 RMS 的阶跃；
  3. 用计量插座校准：总线读数 vs 插座读数误差 <10%。
- 验证标准：录制一段「开/关水壶 10 次」视频，波形阶跃与动作一一对应。

### 阶段二：事件检测 + 规则分类（第 4–6 周）

- 交付物：
  1. CUSUM 阶跃检测，水壶/电饭煲/冰箱事件查全率 >90%（以人工日志为真值，连续 3 天）；
  2. JSON 规则引擎识别 3 类电器，事件级准确率 >80%；
  3. 事件流水 Web 页面 + SQLite 落盘 + 事件附 2 s 波形片段。
- 验证标准：一周「盲测」——家人正常用电，事后对照计量插座日志算混淆矩阵。

### 阶段三：数据集 + ML 分类器（第 7–10 周）

- 交付物：
  1. 标定流水线：计量插座真值自动对齐总线事件，产出 ≥500 条带标签事件；
  2. NILMTK 上跑通 REDD/UK-DALE 基线，确认自研事件检测指标不低于基线；
  3. LightGBM/kNN 分类器替换规则引擎，5 类电器事件级准确率 >90%，推理跑在浏览器/Node 本地。
- 验证标准：留出最后一周数据做测试集，报告查准/查全/混淆矩阵。

### 阶段四：进阶场景最小版（第 11–14 周）

- 交付物：
  1. **故障预警 v0**：冰箱压缩机启动浪涌比与运行占空比的基线 + 3σ 偏移告警（不做诊断，只做「和过去不一样」）；
  2. **关怀提醒 v0**：可配置规则「电器 X 连续 N 天未出现使用事件 → 本地通知」（如水壶 2 天未用）；
  3. 30 天稳定性报告：误报率、漏报率、系统可用率；
  4. 复盘文档：是否值得做 v0.2（电压相位 + 全量下沉 ESP32）。
- 验证标准：人为制造一次「水壶停用 2 天」，提醒按预期触发且无其他误报刷屏。

## 8. 主要风险与对策

| #   | 风险                                                                        | 影响                                  | 对策                                                                                                                            |
| --- | --------------------------------------------------------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **电气安全事故**（CT 副边开路高压、配电箱内触电）                           | 人身伤害，一票否决级                  | 第 3 节安全清单逐条执行；先接负载电阻再夹线；断电操作；不确定就请电工（预算外 50–100 元）                                       |
| 2   | **ESP32 内置 ADC 精度不足**（非线性、噪声大），小负载淹没在噪声里           | 识别下限被抬到 200 W+，冰箱等识别不稳 | BOM 直接含 ADS1256；MVP 目标负载全选 >300 W；用 16× 过采样 + 数字滤波兜底                                                       |
| 3   | **同功率负载不可分**（如 2000 W 水壶 vs 2000 W 取暖器，纯电流幅值无法区分） | 分类准确率天花板低                    | 谐波/浪涌/时长/时段多特征组合；仍不可分则诚实输出「2000W 级电阻性负载」合并类；v0.2 加电压相位（PF）特征                        |
| 4   | **变频电器（变频空调/冰箱）无明显阶跃**，事件检测范式失效                   | 主流新电器覆盖不了                    | MVP 阶段把变频设备列为已知不支持；对其改用「功率包络模式匹配」（爬坡曲线）作为阶段四探索项；产品话术上只承诺定频与电阻性负载    |
