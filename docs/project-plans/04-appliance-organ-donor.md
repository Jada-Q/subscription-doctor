# 项目 4：旧电器的「器官捐献」数据库

> 社区维护的拆机图鉴：拍下坏电器或拆出的模块 → 识别型号 → 给出可回收模块清单、引脚定义与典型复用项目。对抗电子垃圾，服务 maker 社区。

---

## 1. 一句话定位与目标用户

**一句话定位**：当一台电器「死亡」时，告诉你它身上还有哪些「器官」值得移植、怎么取、能用在哪——一个由 maker 社区共建的结构化拆机知识库。

**目标用户**（按优先级）：

| 用户群                       | 画像                                          | 核心诉求                                       |
| ---------------------------- | --------------------------------------------- | ---------------------------------------------- |
| 核心：DIY maker / 电子爱好者 | 玩 Arduino/ESP32、逛立创/淘宝散件、看拆机视频 | 「这台坏微波炉里有什么我能用的？引脚怎么接？」 |
| 次级：维修党 / 翻新党        | 闲鱼回血、社区维修咖啡馆志愿者                | 快速判断残值，找替换件来源                     |
| 外围：环保关注者 / 学生      | 课程项目、STEAM 教育                          | 低成本获得电机、电源、显示屏等教学素材         |

**反目标用户**（明确不服务）：想要专业维修手册的家电维修商（有专业付费数据库），以及想拆电器卖废铜的回收商。

**北极星指标**：每月「成功复用」反馈数（用户标记「我按这条图鉴拆出并用上了某模块」）。

## 2. 冷启动策略（前 100 条数据和前 50 个用户）

冷启动原则：**先自产数据，再换数据，最后才求人贡献。** 单人冷启动，预算 < 500 元（收破烂买旧电器的钱）。

### 2.1 前 100 条数据（目标：上线时已有 100 个模块条目，约 20–25 台电器）

| 来源         | 数量   | 做法                                                                                                                                                                                                                                                                                                 |
| ------------ | ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 自己拆       | ~40 条 | 从闲鱼/小区回收站/家电以旧换新淘 8–10 台最常见电器（微波炉、滚筒洗衣机、波轮洗衣机、空调内机、电饭煲、打印机、电风扇、微波炉、饮水机、旧路由器），每台产出 4–6 个模块条目。自己拆的好处：照片、引脚实测、危险点全部一手可控，是质量基准。                                                            |
| 整理公开资料 | ~40 条 | 系统性整理 YouTube/B 站拆机视频（GreatScott!、DiodeGoneWild、硬核拆解类 UP 主）、iFixit、EEVblog 论坛中的高频模块（洗衣机通用电机、微波炉变压器、打印机步进电机+导轨、ATX 电源），重写为结构化条目并注明来源链接。**只转述事实数据（型号、引脚、参数）+ 自己重绘示意图，不搬运原图**，避免版权问题。 |
| 定向邀约     | ~20 条 | 私信 5–10 位拆机类 UP 主 / 论坛活跃者：「我帮你把视频整理成结构化图鉴页并署名+回链」，对方零成本获得一个长尾流量入口。预期 30–50% 应答率。                                                                                                                                                           |

**选品策略**：优先覆盖「全国保有量大 × 模块通用性强」的电器。前 100 条只做 10 类电器，做深不做广——一台洗衣机的图鉴要完整到「电机型号→引脚→驱动方案→3 个复用项目」，胜过 50 条只有照片的残缺条目。

### 2.2 前 50 个用户（目标：上线 4 周内 50 个注册用户，其中 ≥10 人有贡献行为）

1. **第 1 批（0→10，熟人+垂直社区）**：在数码之家、立创社区、Chiphell DIY 版、V2EX 创造者板块、Reddit r/AskElectronics + r/functionalprint 各发一篇「我把 10 台旧电器做成了器官捐献图鉴」的展示帖，附 2–3 个最有戏剧性的条目（如「微波炉里有 5 样能用的东西和 1 样会杀死你的东西」）。展示帖本身就是内容营销，不是求注册。
2. **第 2 批（10→30，钩子内容）**：每周发布 1 个「复用项目」短图文/短视频（洗衣机电机+ESP32=拉坯机、打印机导轨=激光雕刻机），B 站/小红书/即刻分发，文末「完整引脚定义见图鉴」引流。复用项目是传播钩子，引脚数据库是留存钩子。
3. **第 3 批（30→50，贡献激励）**：发起「悬赏拆机」：列出 20 台「图鉴还没有的电器」清单，完成一台完整条目的用户获得首页署名「捐献者」+ 早期贡献者徽章（编号永久保留）。早期社区的激励是身份和署名，不是钱。
4. **线下补充（可选）**：联系本地 1 家维修咖啡馆 / 创客空间，提供打印版「危险件警示卡」换取摆放二维码。

**冷启动验收线**：4 周后若 50 用户中无人产生任何 UGC（连纠错评论都没有），触发第 8 节风险 R1 的降级预案。

## 3. MVP 范围（先做内容站还是识别工具？）

**推荐：先做内容站（结构化图鉴 + 强搜索），AI 识别放 v2。**

理由：

1. **冷启动期识别必然难用**。视觉识别依赖数据库覆盖度——只有 100 条数据时，识别 10 次失败 9 次，用户拍照→「未收录」→流失，是最差的首次体验。内容站则相反：搜到即有用。
2. **用户的真实查询方式是文字**。坏电器铭牌上有型号，maker 会直接搜「海尔 EB80M39TH 电机」。搜索框 + 良好 SEO 解决 80% 的需求，成本是识别功能的 1/10。
3. **内容站积累的数据正是未来识别功能的训练集**。每个条目的多角度照片 + 型号标签，就是 v2 识别模型的标注数据。顺序反了则两头落空。
4. **SEO 是单人项目最便宜的获客渠道**。长尾词「XX型号 拆机 电机 引脚」几乎零竞争，结构化页面天然适合 SEO；识别工具对搜索引擎不可见。

### MVP 功能清单（4–6 周可单人完成）

**做**：

- 电器/模块结构化条目页（照片、参数、引脚表、危险等级、复用项目链接）
- 全文搜索 + 按「电器类型 / 模块类型 / 难度 / 危险等级」筛选
- 提交表单（带模板的结构化表单，照片必填，登录后可提交）
- 简单审核后台（我一个人用：待审队列、通过/退回/编辑）
- 危险件全站警示组件（见第 6 节）
- 用户系统（仅邮箱/GitHub OAuth，用于署名和贡献统计）

**不做（明确推迟）**：

- ❌ AI 拍照识别（v2，数据 ≥ 500 条后）
- ❌ 评论区 / 私信（用 GitHub Discussions 或外链社群替代，省审核成本）
- ❌ App（PWA 足够，拆机现场用手机浏览器看引脚图即可）
- ❌ 交易/二手撮合（法律与运营成本高，且偏离定位）

**技术选型（低运营成本）**：Next.js + Supabase（Postgres + Auth + Storage 免费档）+ Vercel 免费档，图片走 Supabase Storage + CDN，月成本 ≈ 0 元，到日活几百才需要付费。条目内容存数据库而非 MDX 文件，因为 UGC 需要表单提交和审核流。

## 4. 数据模型设计

核心关系：**电器 (Appliance) 1→N 模块 (Module)，模块 1→N 引脚 (Pin)，模块 M→N 复用项目 (Project)**。另设「模块类型 (ModuleType)」作为跨电器的通用抽象层——这是本数据库最有价值的设计：用户关心的往往不是「这台海尔洗衣机的电机」，而是「洗衣机通用串激电机」这一类。

```
ApplianceCategory（电器品类：洗衣机/微波炉/...）
   └── Appliance（具体型号条目）
          └── ModuleInstance（这台电器里的具体模块）──┐
                  └── Pin（引脚定义）                  │ N:1
                                                      ▼
ModuleType（通用模块类型：串激电机/磁控管/ATX电源...）
                  ▲ M:N
ReuseProject（复用项目）──── ProjectModule（连接表）
```

```sql
-- 电器品类（手工维护的小字典表）
appliance_categories (
  id, slug, name_cn, icon
)

-- 具体电器条目
appliances (
  id            uuid PK,
  category_id   FK -> appliance_categories,
  brand         text,            -- 海尔
  model         text,            -- EB80M39TH
  aliases       text[],          -- 铭牌别名/OEM 型号，供搜索与 OCR 匹配
  year_range    text,            -- "2015-2019"
  photos        jsonb,           -- [{url, caption, angle}]
  teardown_difficulty smallint,  -- 1-5
  hazard_level  smallint,        -- 0-3，取其模块中的最大值（冗余字段，便于列表页标红）
  status        enum('draft','pending','published','rejected'),
  contributor_id FK -> users,
  source_url    text,            -- 资料来源（转述外部拆机时必填）
  created_at, updated_at
)

-- 通用模块类型（知识沉淀层，编辑维护）
module_types (
  id, slug,
  name_cn       text,            -- "洗衣机串激电机"
  description   text,
  typical_specs jsonb,           -- {voltage: "220V", power: "300-500W"}
  hazard_level  smallint,        -- 0安全/1注意/2危险/3致命
  hazard_notes  text,            -- "断电后电容仍带电，需放电"
  drive_guide   md/text          -- 通用驱动方案（如：需调速板或可控硅）
)

-- 模块实例（某台电器里实际拆出的模块）
module_instances (
  id            uuid PK,
  appliance_id  FK -> appliances,
  module_type_id FK -> module_types,
  part_number   text,            -- 模块自身丝印型号
  photos        jsonb,
  location_note text,            -- "后盖左下，4 颗 T20 螺丝"
  extraction_steps md/text,      -- 拆取步骤
  condition_check md/text,       -- 好坏判断方法（万用表量阻值等）
  measured_specs jsonb           -- 实测参数，区别于 module_types 的典型值
)

-- 引脚定义
pins (
  id            uuid PK,
  module_instance_id FK -> module_instances,
  pin_no        text,            -- "1" / "CN2-3"
  label         text,            -- "VCC" / "调速反馈"
  wire_color    text,            -- "红"
  description   text,
  voltage       text,            -- "DC 5V" / "AC 220V ⚠"
  verified      boolean,         -- 实测过 or 来自资料推断
  position      integer          -- 排序
)

-- 复用项目
reuse_projects (
  id, slug,
  title         text,            -- "洗衣机电机 + ESP32 = 陶艺拉坯机"
  difficulty    smallint,
  cover_photo, body_md,
  extra_bom     jsonb,           -- 除拆机件外还需购买的料单
  source_url, contributor_id, status
)

-- 项目 ↔ 模块类型 多对多
project_modules (
  project_id FK, module_type_id FK,
  role text                      -- "主驱动" / "电源"
)

users ( id, handle, avatar, contribution_count, badges jsonb )

-- 轻量纠错（替代评论区）
corrections (
  id, target_table, target_id, field, suggestion, status, user_id
)
```

设计要点：

- **`module_types` 与 `module_instances` 分离**是关键：危险警示、驱动指南、复用项目都挂在类型层，写一次全库复用；实例层只存「这一台里在哪、怎么拆、实测值」。
- **`aliases` + `part_number`** 为未来 AI/OCR 识别预留匹配字段，从第一天就要求贡献者抄录铭牌全文。
- **`verified` 标记在引脚级别**：转述资料与实测数据可信度不同，必须可区分，这是图鉴公信力的基础。
- **`hazard_level` 在类型层定义、电器层冗余**，保证任何列表/卡片视图都能无 join 标红危险件。

## 5. AI 识别方案

### 5.1 现实难度评估：拍照识别整机型号——**难，且性价比低，不应作为 v1 卖点**

| 难点         | 说明                                                        |
| ------------ | ----------------------------------------------------------- |
| 同壳不同芯   | 同一外观模具对应数十个型号/年份配置，外观分类天花板低       |
| 长尾分布极端 | 家电 SKU 数十万，自建分类模型在 <1 万张标注图前没有意义     |
| 坏电器状态差 | 用户拍的是脏污、拆了一半、缺壳的机器，与电商图分布完全不同  |
| 拆出模块更难 | 一颗电机/电源板脱离整机后，视觉上几乎只能识别到「大类」级别 |

结论：**「拍整机照片→精确型号」在本项目数据规模下 2 年内不现实。可行的是降级目标：「拍照→大类 + 候选列表」。**

### 5.2 推荐落地路径（三级漏斗，逐级降级到人工）

```
用户拍照
  ├─ ① 铭牌 OCR（首选，准确率最高）
  │     铭牌照片 → OCR 提取品牌/型号/参数文本
  │     → 与 appliances.model / aliases 模糊匹配（trigram）
  │     → 命中：直达条目页；未命中：进 ②
  ├─ ② 多模态大模型识别大类（LLM API，按次计费，零训练）
  │     调用视觉 LLM："这是什么电器/什么模块？给出大类和置信度"
  │     → 返回 module_type 级别候选 → 跳转该类型的通用图鉴页
  │     （即使没有精确型号条目，类型页的驱动指南/危险警示依然有用）
  └─ ③ 人工确认兜底（同时是数据采集入口）
        「求鉴定」队列：照片进社区悬赏区，认出来的用户得贡献分；
        我本人每天清一次队列。每一次人工鉴定 = 一条新的标注数据。
```

实现说明：

- **① OCR 铭牌是 v1.5 就能做的**：成熟开源/云 OCR（如浏览器端 Tesseract/PaddleOCR 或云 API）+ 数据库模糊匹配，开发量约 1 周。产品上引导语直接写「请拍铭牌，不要拍整机」，把问题从 CV 难题变成 OCR 易题。
- **② 用通用多模态 API 而不是自训模型**：按调用付费、零标注成本，识别「这是个微波炉变压器」这种大类问题的准确率已经够用。配每日调用限额控制成本（如每用户 5 次/天）。
- **③ 人工兜底不是耻辱而是飞轮**：早期社区「帮人认元件」本身就是高粘性互动（参考 r/whatisthisthing），且持续产出标注数据，反哺未来识别能力。
- **所有识别结果一律带「AI 推测，未经实测验证」标签**，与第 6 节安全免责联动——识别错误若导致用户误判危险件，责任风险极高，宁可保守。

## 6. 内容审核与安全免责

拆电器有真实的致死风险，本节是全项目的合规底线，**MVP 第一天就必须齐备，不可推迟**。

### 6.1 危险分级（落在 `module_types.hazard_level`）

| 级别   | 标识            | 典型对象                                                                 | 站内处理                                                                                                       |
| ------ | --------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| 3 致命 | 🔴 红色全屏插页 | 微波炉高压电容+磁控管（铍氧化物）、CRT 高压包、空调/冰箱压缩机制冷剂回路 | 条目页进入前强制阅读警示并点击确认；磁控管陶瓷件标注「严禁破碎，含铍」；制冷剂标注「禁止私自排放，违法且有毒」 |
| 2 危险 | 🟠 橙色横幅     | 一切 220V 市电部分、大容量电解电容、洗衣机门锁 PTC、锂电池组             | 拆取步骤第一条强制为「断电+电容放电方法」，锂电池条目必含鼓包/穿刺警示                                         |
| 1 注意 | 🟡 黄色提示     | 弹簧、玻璃、利边钣金、热熔部件                                           | 行内提示                                                                                                       |
| 0 安全 | 无              | 外壳塑料、旋钮、低压小电机                                               | —                                                                                                              |

**红线内容（直接拒审）**：任何教唆改装微波炉变压器做点焊机以外用途的高压实验、拆解烟雾报警器放射源、绕过安全联锁装置的内容；含铍部件的打磨/破碎教程。

### 6.2 审核流程（单人可运营）

1. **结构化表单前置拦截**：提交模块条目时必选危险等级；选了 2/3 级则强制填写「断电与放电步骤」字段，不填无法提交。模板即审核——把安全要求做进表单，比事后人审便宜。
2. **先审后发**：MVP 阶段所有条目人工过审（预估每条 5–10 分钟，日均 <30 分钟）。审核 checklist：危险等级是否低估、照片是否清晰、引脚 `verified` 标记是否如实、来源链接是否齐全。
3. **纠错通道替代评论区**：`corrections` 表 + 「报告错误」按钮，避免开放评论带来的审核负担。
4. **量表自动化（v2）**：条目量 >500 后引入「2 名老贡献者复核 = 自动通过」的信任分机制。

### 6.3 免责声明（法务最低配置）

- 全站页脚 + 注册时勾选 + 每个 🔴🟠 条目顶部，三处展示《免责声明》：内容由社区提供仅供参考、拆解操作风险自负、未成年人须在成人监护下操作、本站不对人身财产损失负责。
- 引脚/电压数据标注「以实测为准，错误难免」；AI 识别结果标注「机器推测，操作前必须自行核实」。
- 上线前花半天参考 iFixit 的 Terms 与免责文本结构本地化一份；若项目长大（>1 万 MAU）再付费咨询律师。

## 7. 里程碑（4 阶段）

| 阶段                | 周期        | 内容                                                                     | 可验证交付物（验收标准）                                                                                                               |
| ------------------- | ----------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| **M1 私有图鉴**     | 第 1–4 周   | 数据模型建库、条目页/搜索/提交表单/审核后台、危险警示组件；自拆 8 台电器 | ① 线上可访问站点；② ≥40 个模块条目（含 ≥10 个带完整引脚表）；③ 全部 🔴 级条目有强制警示页；④ 提交→审核→发布全流程跑通                  |
